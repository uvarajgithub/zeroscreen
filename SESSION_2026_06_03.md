### 3. Bugs Found & Fixed (ALL DEPLOYED TO VPS)

#### Bug 1 — T5 EOD exit never fired (CRITICAL)
- **File**: `src/index.ts` line 1404
- **Problem**: `if (tradeCount >= 5) return` was BEFORE the trail block → T5 never got trail updates or EOD exit
- **Fix**: `if (tradeCount >= 5 && !activeTrade) return`
- **Impact**: T5 today should have exited at +155 pts — was skipped entirely

#### Bug 2 — lastExitPts stored wrong value
- **File**: `src/index.ts` line 1454
- **Problem**: `lastExitPts = trail.peakPts` (always positive) instead of `trail.pts` (actual P&L)
- **Fix**: `lastExitPts = trail.pts`

#### Bug 3 — Re-entry blocked after losing trade
- **File**: `src/index.ts`
- **Problem**: `if (lastExitPts >= 0)` gate was preventing re-entry after a loss
- **Fix**: Removed the condition entirely (matches backtest logic)

#### Bug 4 — Dashboard ₹ P&L wrong for futures trades
- **File**: `server_vps.js` (5 locations)
- **Problem**: Used `(premiumExit - premiumEntry) × qty` formula (for options) on futures trades → showed completely wrong ₹ (T1 showed +₹8,016 when correct was +₹156)
- **Fix**: If `symbol.includes('FUT')` → use `pnl × qty` instead

#### Bug 5 — Telegram showed raw unrealized as "P&L"
- **File**: `src/index.ts` monitorCandleBreakouts
- **Problem**: Two independent 15s timers (runBot + monitorCandleBreakouts). When TG fired before runBot on the exit candle, it showed `-131 pts P&L` while the actual trail was `+5 pts`
- **Fix**: Recompute trail inline in TG, show "🔒 Trail locked: +X pts" prominently + "Spot: ±X pts (live vs entry)" separately. Also fixed `Day+lock` to include current trade's locked amount.

#### Bug 6 — VPS ENTRY_PRICE_UPDATE overrode DrishtiState.entry with futures fill
- **File**: `src/index.ts` (VPS-only code, not in index_vps.ts)
- **Problem**: `DrishtiState.entry = order.average_price` (futures LTP ~300-400 pts above index) → trail would NEVER develop in real mode → every trade would hit SL at -150 pts
- **Fix**: `DrishtiState.entry = bc.close` always; `entryPrice` still shows futures fill for display

#### Bug 7 — Stale futures LTP at entry causing huge losses
- **File**: `src/index.ts`
- **Problem**: `getCurrentPrice()` returned cached LTP from BEFORE a large candle. After C12's +480pt move, LTP was still 54062 (old price) vs fair value 53930 → overpaid 161 pts = ₹4,830 per trade → turned index profits into futures losses
- **Fix**: Compute fair futures price = `bc.close × (1 + 7% × DTE/365)`. If `|rawLTP - fairFutures| > 100 pts` → use fair price instead
- **Impact**: T2-T4 today: real P&L went from **-₹5,760 → +₹8,715** with fix

#### Bug 8 — Backtest C0 candle mismatch
- **File**: `bt_drishti_5yr.js`
- **Problem**: Backtest used 9:15 AM candle as C0. Live bot seeds 9:15 and uses 9:30 AM as C0. Different C0 → different context/signals on some days
- **Fix**: `today.slice(1)` in backtest to skip 9:15 candle → C0 now = 9:30 AM (matches live bot)

#### Bug 9 — Backtest EOD timing mismatch
- **File**: `bt_drishti_5yr.js`
- **Problem**: Old code: `isEOD = c.h === 15 && c.m >= 30` → never true for 3:15 PM candle (m=15). Recent data has no h/m at all → isEOD always false → force-close workaround
- **Fix**: `isEOD = c.h !== undefined ? (c.h > 15 || c.h === 15 && c.m >= 15) : (i === todayCandles.length - 1)` + add h/m from candle index for recent data

### 9. Strategy Quick Reference

**DRISHTI V1 — INSIDE day entry (most common):**
- Structural break: candle close < prev candle low → PE. Close > prev high → CE
- C0 momentum: if C0 body% > 55% → immediate CE/PE on C0 close
- Re-entry: first candle after exit with |body| > 40% → re_same_dir or re_reverse

**Trail LOCK10:**
- Peak = max favorable intrabar move from entry
- Trail = peak − 10 pts (locked amount)
- Exit when: candle close ≤ trail locked amount (not intrabar — only candle close!)
- EOD: exit at 3:30 PM (3:15 PM candle close)

**Today's T1 explained:**
- PE entry 53082, C11: Low=53067 (peak=15 pts, trail=5 pts), Close=53213 (went 131 pts against)
- Trail fires: closePts (-131) ≤ trailStop (+5) → EXIT at +5 pts (NOT a loss despite -131 unrealized)
